A survey of JDownloader 2 area by area, with every feature checked against the
KnightLoader source. It exists to be gone through together: read a table, decide
per row, and the decision is recorded in the Verdict column as we go.

**928 features** found across 9 areas.

| Status | Count | Meaning |
|---|---|---|
| have | 79 | present and working here |
| partial | 202 | some of it exists, the table says which part is missing |
| missing | 647 | not built |

Effort is judged for *this* architecture: S is under a day, M a day or two,
L several days, XL a project. The Blocker column is empty unless something
genuinely stands in the way.

## 1. Extensions and add-ons

JD2 has exactly 11 extension modules: Extraction + Tray Icon ship inside the base install (both enabled by default), Growl ships on macOS only, and 8 are optional downloads listed in Settings > Extension Modules (Event Scripter, Folder Watch, Scheduler, JD Shutdown, AntiStandBy, Info Bar, Support Chat, Translator) — all off until installed, and all default-disabled after install except AntiStandBy. Verified against the local install (C:\Program Files\JDownloader: extensions/Extraction.jar is the only jar present, update/versioninfo/JD/serverOptions.json lists the 10 downloadable jars) and against mirror/jdownloader master (ExtensionController.java MAPPING + initOptionalExtensions is the authoritative registry). The JD1-era add-ons named in the brief (Web Interface, Remote Control, Merge to one file, Auto-Upload) do not exist as JD2 extensions — their capabilities were absorbed into MyJDownloader, the Deprecated API, and the Extraction extension's split-file joining.

## 3. Toolbar, main menus and global controls

Grounded in JD2 source: MenuManagerMainToolbar.java and MenuManagerMainmenu.java literally encode the shipped default layouts, StatusBarImpl.java the status bar, MenuManagerTrayIcon.java the tray menu, and GuiTranslation.java the English/German labels. ## 4. Reconnect, proxies and network

Grounded in the mirror/jdownloader source: reconnect is a plugin registry (ReconnectPluginController) of RouterPlugins each contributing its own settings GUI card into Settings > Reconnect, driven by Reconnecter + IPController (IP check is the success oracle, so disabling it cripples the wizard and recorder). Proxies are not a single dialog but a table of AbstractProxySelectorImpl rows in Settings > Connection Manager; "rotation" is emergent - for free downloads JD tries every enabled selector in parallel, for premium it takes the first, with per-row FilterList (whitelist/blacklist on `user@domain` regexes) doing per-hoster assignment and a per-row ban list handling failures. Interface binding is not a separate feature but the "Direct Gateway" proxy type (HTTPProxy.TYPE.DIRECT bound to a local NIC address), and bandwidth limiting is a 2-second watchdog (DownloadSpeedManager) that redistributes the global byte/s budget across per-download handlers and their per-chunk throttled connections.

## 5. Settings (complete settings tree)

JD2's settings sidebar is a flat list, not a tree, and its exact order is hardcoded in SettingsSidebarModel.fill(): General, Reconnect, Connection Manager, Account Manager, Basic Authentication, Plugins, Captchas, User Interface, Bubble Notify, My.JDownloader, Linkgrabber Filter, Packagizer, Archive Extractor, Tray, Advanced Settings, Extension Modules, then every enabled extension alphabetically. There is no "Downloads" or "Passwords" node: download options sit under General, and passwords are split across Account Manager, Basic Authentication, Extraction's password list, the tray/GUI password and My.JDownloader. Advanced Settings is not a panel of its own options but a generic raw editor over every @AboutConfig-annotated key in every ConfigInterface (core + plugins + extensions), which is why hundreds of real features have no GUI panel at all.

## 8. Automation, rules and scripting

Packagizer rules and LinkGrabber filter rules share one condition engine (org.jdownloader.controlling.filter.FilterRule: 11 condition types, each with its own matcher enum) and differ only in what they do on a match, so a clone should build the matcher once and reuse it. Nearly all automation surfaces converge on the same internal RemoteAPI: the MyJDownloader cloud API, the local Deprecated API on 3128 and the Event Scripter's callAPI() all speak the identical namespace/method vocabulary, and CLI `-set` also routes through it. Ordering matters and is load-bearing: filters run before the Packagizer, Packagizer rules run top-to-bottom by an explicit `order` column, and .crawljob can opt in to running before or after the Packagizer (setBeforePackagizerEnabled / overwritePackagizerEnabled).

## 9. Interface behaviour and quality of life

JD2's entire menu/toolbar/context-menu/bottom-bar layer is data-driven (ContextMenuManager + MenuItemData), so nearly every button's label, icon, visibility and keyboard shortcut is user-editable via Settings > User Interface > Menus and Toolbars - that customisation engine is the biggest structural fact in this area. Most quality-of-life switches do not live in the visible settings panels but in Settings > Advanced Settings, spread over GraphicalUserInterfaceSettings, LAFSettings, UpdateSettings, TrayConfig, SoundSettings, ShortcutSettings and RemoteAPIConfig, found by searching the key name. ## How to use this

The Verdict column is empty on purpose. Going through an area, put one of
these in it and the list becomes the plan:

- **build** — worth having, schedule it
- **later** — worth having, not now
- **no** — deliberately not, for the reason in Blocker or because it does not
  fit what this is for

A ⚠ on a feature name means the survey could not confirm that detail against a
primary source; treat those as "probably, verify before building".
